# 站立识别 —— 快速上手（发布包 v1）

用 YOLO26s-pose 做人体姿态估计，识别画面中**站立**的人并输出**渲染视频**（只标注站立者）。
本包内已含模型、算法、示例素材、结果视频与逐帧数据，开箱即可运行。

---

## 0. 包内目录

| 目录 | 内容 |
|---|---|
| `00_测试素材/` | 3 段 90 秒、720p 测试片段（可直接用来试跑） |
| `01_算法与模型/` | 算法源码（`stand_detector.py` 等 4 个模块）、模型 `yolo26s-pose.pt`、`run.bat`、依赖清单、单元测试 |
| `02_使用说明/` | 本文件 + 完整文档 `README.md` |
| `03_结果视频_stand_v/` | 3 个机位的渲染结果（有骨架 / 无骨架 各一版） |

| `06_透视标定曲线/` | 各机位的透视补偿曲线（同机位复用可省去自动标定时间） |

## 1. 环境

* Python 3.10+（推荐 3.12）
* 依赖：`pip install -r 01_算法与模型/requirements.txt`（主要是 ultralytics、torch、opencv-python、pillow、imageio-ffmpeg）
* 显卡：NVIDIA GPU 可选。**有 CUDA 时**自动用 GPU 解码(NVDEC)/推理/编码(NVENC)；**没有也能跑**，会自动回退到 CPU 与 OpenCV 编解码（速度慢一些）

> 首次运行会有约 9 秒的模型/CUDA 预热，属正常现象（日志里"稳态 FPS"已剔除该时间）。

## 2. 跑一段看看（用包内示例素材）

```bash
cd 01_算法与模型

# Windows 快捷方式（自动找 Python）
run.bat ..\00_测试素材\教室前端_左_122459_600-690_720p.mp4

# 或直接调用
python stand_detector.py --source ..\00_测试素材\教室前端_左_122459_600-690_720p.mp4 ^
    --output ..\结果_示例.mp4 --csv ..\结果_示例.csv --json ..\结果_示例.json
```

跑完得到：`结果_示例.mp4`（渲染视频）+ `.csv`（逐帧每人一行）+ `.json`（汇总与每人站立时间段）。

## 3. 处理自己的视频

```bash
# 基本用法：输出 720p 渲染视频
python stand_detector.py --source D:\videos\教室.mp4 --out-width 1280

# 长视频只处理某一段（600~690 秒）
python stand_detector.py --source D:\videos\教室.mp4 --start-time 600 --end-time 690 --out-width 1280

# 不画骨架（只要框+标签）
python stand_detector.py --source D:\videos\教室.mp4 --out-width 1280 --no-skeleton

# 同一机位复用标定曲线（省去每次 10~15s 的自动标定）
python stand_detector.py --source D:\videos\教室.mp4 --persp-calib 06_透视标定曲线\我的机位.json
```

常用参数（完整见 `--help` 或 `README.md`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--source / -s` | 必填 | 视频路径；摄像头填 `0` |
| `--output / -o` | `output/<名>_standing.mp4` | 输出视频 |
| `--out-width` | 0 | 输出宽度，4K 源建议 `1280`（速度提升明显） |
| `--annotate` | `standing` | `standing`=只标注站立者；`all`=标注所有人 |
| `--no-skeleton` | 关 | 只保留框+标签，不画骨架 |
| `--standing-min-score` | 0.80 | **精度门槛**：平滑置信度低于该值不标注、不计数 |
| `--start-time / --end-time` | 0 / 0 | 只处理某一段（秒） |
| `--persp-calib` | 无 | 透视补偿曲线文件（存在则加载，不存在则计算后保存） |
| `--no-persp` | 关 | 关闭透视补偿 |

## 4. 输出怎么读

**渲染视频**：只标注站立的人（绿色框 + `Standing 0.xx` 标签），左上角显示帧号/FPS/时间与站立人数。

**CSV（逐帧逐人）**关键列：

| 列 | 含义 |
|---|---|
| `label` | 该帧的即时判定（STANDING / SITTING / LYING / UNKNOWN） |
| `is_standing` | **最终结论**：时序状态为站立且平滑置信度 ≥ 门槛（默认 0.80）时为 1 |
| `smooth_score` | 用于门槛与显示的平滑置信度 |
| `score` / `coverage` | 即时分数 / 证据覆盖率（coverage<0.5 说明关键点不足，通常是腿被遮挡） |
| `held` | 1=该帧没检测到、由补检/沿用给出（数据里保留便于追溯） |
| `dup` | 1=该帧因去重未绘制、未计数（同一位置重复轨迹被抑制） |
| `persp_k_leg` / `persp_k_asp` | 该帧实际施加的透视补偿系数（1.0=未补偿） |

**JSON**：`totals` 汇总（站立帧数、最大同时站立、标签直方图）、`tracks[]` 每人的站立时间段与时长、
`algorithm` 里记录了本次用的全部阈值与透视曲线、`performance` 里是各阶段耗时。

## 5. 效果与限制（实测数据）

* 4K 监控 → 720p 渲染：**约 30~45 FPS**（RTX 5070 Laptop，FP16）
* 站立判定依据 6 个几何特征（躯干竖直度、髋-踝跨度、膝角、全身伸展比、框高宽比、髋部离地比）
  + 时序状态机（三状态 Viterbi，禁止"非站立↔站立"直跳），漏检时做定向补检
* **精度门槛 0.80**：置信度不足的站立估计不标注（可调）
* **遮挡**：腿部完全被遮挡且无历史证据时给"未知"（不猜）；`coverage` 小于 0.5 的框用虚线表示"证据不足"
* **摄像头正下方**：俯视会把纵向几何压扁，本包用"按框底行自动标定的透视补偿"修正
  （实测把该区域站立者标注率从 0% 提到 97%），且**不影响其他区域已有结果**

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 首次运行卡住约 10 秒 | 模型/CUDA 预热，正常 |
| 速度慢 | 加 `--out-width 1280`；确认在用 GPU（日志"设备: 0 (FP16)"）；或 `--no-recheck` |
| 框里有虚线框 | 该帧关键点不足（多为腿部被遮挡），属"证据不足"提示 |
| 想连坐着的人也标出来 | 加 `--annotate all` |
| 想更严格/更宽松 | 调 `--standing-min-score`（如 0.85 / 0.75） |
| 换了机位结果变差 | 透视曲线与机位绑定：删掉旧的 `--persp-calib` 文件让它重新标定 |
| 想复现本包的结果 | 用 `00_测试素材/` 的片段 + `06_透视标定曲线/` 对应曲线，命令见 `05_逐帧数据/` 同名 JSON 的 `algorithm`/`performance` 字段 |
